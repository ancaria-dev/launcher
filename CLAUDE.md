# launcher

Workspace rules, target build, release chain, and elevation: see `../CLAUDE.md`.

## Install layout

- The launcher is one Windows executable, `dist/Sacred Mod Loader.exe`, placed in the game folder. It installs its payload, shows mods and hook sites in WebView2, saves choices, starts the host, then the game.
- It installs `protocol.exe`, `api.jar`, `zygote.jar`, and `VERSION` into `<game>/launcher/`. Mods live in `<game>/mods`. The agent is inside `protocol.exe`; there is no agent folder.
- Never write outside the game folder: not `%TEMP%`, `%ProgramFiles%`, `%LOCALAPPDATA%`, a system-wide install, or a registry key. Uninstalling the loader means deleting the game folder. Tests write into `t.TempDir()`.
- The only files written beside the game rather than under `launcher/` are the two pureHD files.
- State lives in `<game>/launcher/launcher.json`, plain JSON so a human can read it. A corrupt file is ignored.

## Payload and build

- `install/payload/` is generated by `tools/build.ps1`. Never edit it; the next build deletes it.
- Never stage a mod into the payload. Mods come from a repository at run time.
- `build.ps1` builds coderpack first (so `gen/addr.js` exists), then protocol with `PROTOCOL_AGENT` pointing at the coderpack sibling. Without that variable the host build could take another agent, and the launcher would silently miss the change.
- Without siblings, `build.ps1` downloads `protocol.exe`, `api.jar`, and `zygote.jar` from the releases pinned in `dependencies.json`. Only Go is needed then. `-Protocol none -Coderpack none` forces this path.
- CI always uses the download path with no siblings. Exercise the from-source path locally when you change how sibling outputs are built or staged.
- `build.ps1` passes `-Mappings` to `addr.py` only when that path contains `mappings.json`; otherwise `addr.py` uses its own fallback. `-Coderpack none` needs no mappings.
- The build stops unless the staged `protocol.exe --hooks` names hook sites. A host with none has no agent.
- `Unpack` runs only when `<game>/launcher/VERSION` differs from the embedded one. It writes files, never replaces a directory, and skips names starting with `.`, so a JDK in `launcher/java` survives.
- `Unpack` renames a file it cannot overwrite (a running executable) to `<name>.old` first.
- `Unpack` creates `<game>/mods` on every run, before the version check, because `go:embed` drops empty directories.
- The only thing `Unpack` deletes is the old `<game>/launcher/agent` folder, and only on a version change.
- `tools/rsrc` writes the icon and version block into `rsrc_windows_amd64.syso` in-house. Never replace it with `go-winres` or `rsrc`: CI has only Go.
- Keep `tools/rsrc` unit tests. A misplaced version-block padding or wrong icon stride links fine and silently shows empty properties or Go's default icon.
- `tools/rsrc/sacred.ico` and `ui/web/icon.png` come from `tools/rsrc/icon.py`. `.version` stamps both the version block and the payload.

## Commands

- `pwsh tools/build.ps1 [-Bump]`: stage the payload and build. `-Bump` raises the patch number in `.version`. `-Protocol`, `-Coderpack`, `-Mappings` point at non-sibling checkouts.
- `pwsh tools/install.ps1 [-Bump]`: build and copy into the game folder. It reads `.local.settings` (uncommitted), one line: `sacred=D:\SteamLibrary\steamapps\common\Sacred Gold`. Without the file it throws, as expected.
- Tests: `go vet ./...` and `go test ./... -count=1`.
- Run the build before the tests. `hooks/hooks_test.go` runs the staged `protocol.exe --hooks` and skips when the payload is absent; a green run on a clean checkout has not checked it.
- Tests never contact external services. Registry tests serve index, jar, and icon over `httptest` TLS through `fetch.Transport`.
- When a foojay response shape changes, save a fresh response into `java/testdata` with curl; never hand-edit a fixture.
- `update.Apply` has no automated test. After touching it, verify by hand: build with a lowered `.version`, run it in a folder holding only an empty `Game.exe`, and check that `VERSION` names the downloaded release.

## Game executable

- Spell the executable names only in `game/exe.go`. `tools/install.ps1` repeats them because PowerShell cannot read Go.
- `game.Find` tries `pureHD.exe`, `Sacred.exe`, `Game.exe`, ignoring case.
- Decide the build by version, never by file name. `game.Version` reads the `VS_FIXEDFILEINFO` numbers (2.0.2.118 for the wrapper, 2.0.2.28 stock), never the `FileVersion` string ("2.28" vs "2.0").
- `game.Expected` must move whenever the address table does. coderpack's `agent/signatures.json` names the same build separately; there is no shared source.
- A mismatched or version-less executable is a caution (`--warn`), not a refusal. Play asks first through the pureHD dialog, and Run anyway always starts the game.

## pureHD

- The archive is `https://ancaria.dev/files/sacred.purehd.zip` from the site's R2 bucket. `purehd.Checksum` and `purehd.Size` pin it; a replaced file needs a launcher release that raises both.
- Download to `<game>/launcher/purehd.part`, unpack to `purehd.new`, and require the exe to report `game.Expected` before touching the game folder.
- Move any existing file of either name, any case, to `<game>/launcher/purehd-backup/<time>/` before placing the new ones. Take names only from `purehd.files`, never from the archive.
- Never touch the stock `Sacred.exe`; `game.Find` prefers `pureHD.exe`.
- Abort works until files start moving; then `Abortable` is false. `purehd.Sweep` clears `.part` and `.new`, never backups.

## Java

- `java.Find` checks `<game>/launcher/java`, then `$JAVA_HOME/bin/java.exe`, then `java` on `PATH`, and returns the first JDK 21 or newer. It continues past an older one. With none suitable it returns the first found so the page can name it.
- Show which Java won above Play in every case.
- Read the version from the JDK's `release` file. Run `java -version` only for a `PATH` java not laid out like a JDK.
- Pass `--java <path>` on Play whenever Java was found; omit the flag when none was.
- Never hardcode a vendor or version list. Both come from the foojay Disco API, filtered by `Vendors` and `Versions`. Never assume a default pair stays downloadable; `Resolve` reports unavailable and browser-only builds.
- Never trust `directly_downloadable` as a query filter. `readPackages` checks it on every entry.
- Oracle's checksum comes as `checksum_uri`, not `checksum`; `Locate` fetches it. Reading only the field verifies nothing on the default vendor.
- Keep `javafx_bundled=false` in the query; Zulu and Liberica otherwise return a second, much larger package.
- Download to `java.part` while hashing, unpack to `java.new`, swap over `java` at the end. Delete a file whose checksum disagrees; never keep a partial or mismatched archive under any name. `java.Sweep` clears leftovers.
- `Unzip` drops the single common root folder, whatever the vendor named it. The zip guard is `filepath.IsLocal`; refuse an absolute entry, never trim it.

## Self-update

- `update.Latest` reads `releases/latest` and picks the asset by `.exe` extension, never by name: GitHub rewrites spaces in the name to dots.
- `update.Newer` compares with `pin.Parse`, never as strings. A `dev` build is newer than every release.
- The check runs in a goroutine and fails silently; being offline is normal.
- Download to `<game>/launcher/update/launcher.exe` under a fixed name. Check the published size and the `MZ` header; GitHub publishes no digest, so never claim one is verified.
- `update.Apply` renames the running exe to `<name>.old`, renames the new one into place, and starts it. Undo the first rename if the second fails. `update.Sweep` clears leftovers.

## Mods and repositories

- A remote is a git repository with `sacred.mods.repository.json` at its root; nothing runs git. `registry.Candidates` tries the GitHub raw and API shapes, then GitLab, then two Gitea shapes, and remembers the winner in `Remote.Raw`.
- `Normalize` requires `https://` and a `.git` suffix, deliberately.
- `registry.Official` is a list and cannot be removed. The player's own remotes live in `conf.Remotes`.
- Never hide or refuse a mod because another mod's `conflicts` names it. That comes from someone else's index and would let a hostile index remove a rival. Show `Clash.Sentence` in amber under both rows.
- Never hide an incompatible mod. Draw it switched off with a disabled checkbox and `Mod.Refusal` in red, and never put its id in the enabled list.
- `mods.Loader` and `Loader.Refuse` check a descriptor's `api` and `loader` ranges. A missing `api` is refused, as zygote does; a missing `loader` is accepted.
- `Mod.Refusal` is a whole Go sentence naming the requested range. The page's wording is only a fallback.
- Hide only the same id offered by two repositories. An installed mod is not offered again; a different version gets an Update button.
- Install a downloaded jar only when its SHA-256 matches the index, its own descriptor's id matches the offered id, and its own `api` and `loader` ranges accept this launcher. Read the ranges from the jar, never from the index.
- Never let a network value choose a path. Build the jar file name from the validated id and version; name the icon cache by id; `safePath` rejects `..`, a leading slash, or a backslash. A release asset's name never names a file either.
- An update removes the old jar before placing the new one.
- Icons: data URIs only (the window has no origin), at most 256 KB, fetched one at a time, and `encode` rejects non-images including SVG.
- Tokens go through `secret`: DPAPI when `secret.Works()`, otherwise plain text. Keep the sentence under the field aligned with what `secret.Seal` will do.
- `mods.API` must move with `Api.VERSION` and `Verifier.API`; `pin` is one of three range parsers. See `../coderpack/CLAUDE.md`.

## Page and window

- Nothing on the page waits for the network. WebView2 bindings run on the window's message thread; slow work runs in a goroutine (`java.Work`, `purehd.Work`, registry `Work`) and the page polls, every 200 ms while a job runs.
- One registry job at a time. While it runs, disable every other row button; `Work.start` silently refuses the rest.
- A row button that starts work reports progress on itself. Build it with `act` in `app.js`; `Progress.ID` names the mod.
- Paint the pressed button before Go answers. `paintRows` updates buttons in place and never calls `render`.
- Never use `<a href>`. `ui.Open` hands http/https URLs to ShellExecute and refuses every other scheme.
- Save settings on every change, not only on Play. The flags field debounces 250 ms.
- `conf.OffHooks` stores what is off, so a new hook arrives switched on. `Conf.Enabled == nil` means all mods.
- Draw hook sites only from `hooks.Ask` (`protocol.exe --hooks`). Never add a hand-written hook table. An empty answer draws no hooks.
- Pass `--no-hook` only with a non-empty list; an empty value reaches the agent as one empty name.

## Host and process

- Start the host before the game. A late attach can miss a world load.
- `Session.Wait` waits for the game, sleeps 500 ms for a clean Frida detach, then kills the host.
- The binary is built `-H=windowsgui`. Report startup failures with `messageBox`; `fmt.Println` is invisible.
- A game under `Program Files` needs an elevated launcher to write the payload. `main.go` says so.
- The host inherits the launcher's elevation. An unelevated launcher and an elevated game give an endless wait, not an error.

## Windows traps

- Clear QuickEdit (`0x0040`) in the `--debug` console, or a stray click blocks the host's writes. Clear `ENABLE_MOUSE_INPUT` (`0x0010`) too, or scrolling breaks. Neither takes effect without `ENABLE_EXTENDED_FLAGS` (`0x0080`). `dontPauseOnClick` in `console.go` does this.
- `SetProcessDpiAwareness` returns an HRESULT; zero is success. Never read it as a BOOL.
- Declare DPI awareness before any window exists, then size the window in real pixels with `ui.scale`.
