# Sacred Mod Loader

Один файл устанавливает и запускает мод-лоадер для Sacred Gold. Он распаковывает
хост и Java-компоненты в папку игры, показывает установленные и
доступные моды, запоминает выбор и запускает Sacred.

## Установка и запуск

1. Положите `Sacred Mod Loader.exe` в папку Sacred Gold, где находится
   `pureHD.exe`, `Sacred.exe` или `Game.exe`.
2. Запустите файл. Лаунчер создаст папки `launcher` и `mods`. Содержимое
   `launcher` обновится, когда изменится версия встроенного payload.
3. Отметьте нужные моды и нажмите Play.

Пока игра работает, окно лаунчера скрыто. После выхода из Sacred оно появляется
снова. Лаунчер сначала запускает `launcher\protocol.exe`, затем игру, а после её
закрытия останавливает хост.

Готовый exe содержит весь сам лоадер, но не содержит модов. Моды можно
установить на вкладке Available или положить вручную в папку `mods`. При
следующем запуске jar-файл с читаемым `META-INF/declaration.toml` появится на
вкладке Installed.

Настройки записываются в `launcher\launcher.json` после каждого изменения.
Выбранные моды, отключённые хуки, дополнительные флаги и режим консоли
сохранятся, даже если закрыть окно без запуска игры.

## Обновление лаунчера

Весь лоадер едет внутри одного exe, поэтому обновление — это заменить его и
запустить заново. При старте лаунчер спрашивает GitHub, есть ли релиз новее, и
если есть, под номером версии в шапке появляется строка **Version X is
available. Download & install now**. Если новее нет или GitHub недоступен, не
появляется ничего.

По ссылке открывается окно, которое сразу начинает скачивание и не закрывается,
пока оно идёт. Файл кладётся в `launcher\update` внутри папки с игрой: ничего
не пишется ни в `%TEMP%`, ни вообще за пределы игровой папки. Когда скачивание
закончится, появится кнопка **Install & Restart**. Лаунчер заменит себя,
запустит новую версию и закроется. Старый файл останется рядом как
`Sacred Mod Loader.exe.old` и будет удалён при следующем запуске.

Моды, настройки и скачанная Java остаются на месте. Если что-то пошло не так,
окно покажет причину и ссылку на страницу релиза, которая откроется в браузере.

## Моды и репозитории

Вкладка Installed показывает моды из `<папка игры>\mods`. Лаунчер читает их
дескрипторы как обычные записи zip-архива и не запускает Java-код до нажатия
Play. Установленный мод можно включить, выключить, обновить или удалить.

Вкладка Available загружает список из официального репозитория
`https://github.com/ancaria-dev/mods.git`. Дополнительный источник должен быть
Git-репозиторием с файлом `sacred.mods.repository.json` в корне. Вставляйте
HTTPS URL для клонирования с суффиксом `.git`. Сам Git лаунчер не запускает и
репозиторий целиком не клонирует.

Перед установкой лаунчер проверяет SHA-256 из индекса, идентификатор внутри jar
и диапазоны совместимости с API и версией лоадера. Не прошедший проверку файл не
остаётся в `mods`.

Мод, собранный для другой версии API или лаунчера, остаётся в списке. Его строка
приглушена, под описанием указана причина несовместимости, а флажок недоступен.
Такой мод не запускается. Исправить это может автор мода, пересобрав его для
текущего API и лоадера или изменив заявленные диапазоны версий.

Для закрытого репозитория можно указать токен. Если Windows DPAPI доступен,
лаунчер шифрует токен учётной записью текущего пользователя перед записью в
`launcher\launcher.json`. Такой токен нельзя расшифровать под другой учётной
записью или на другом компьютере. Если DPAPI недоступен, интерфейс предупреждает
о сохранении токена открытым текстом.

## Java

Моды работают в отдельной JVM, которую запускает хост. Без подходящего JDK игра
всё равно стартует, но ни один мод не загрузится. Текущая версия Java и её
источник указаны над кнопкой Play.

Лаунчер проверяет три места в этом порядке:

1. `launcher\java`, куда он ранее скачал JDK
2. `$JAVA_HOME\bin\java.exe`
3. `java` из `PATH`

Используется первая найденная Java версии 21 или новее. Если подходящей версии
нет, интерфейс всё равно показывает первую найденную Java и объясняет, почему
она не годится.

Кнопка Get Java открывает каталог дистрибутивов и поддерживаемых GA-версий Java
21 или новее. Данные приходят из
[foojay](https://api.foojay.io/disco/v3.0/), на котором работает
javaalmanac.io. В списке остаются поддерживаемые и доступные сборки OpenJDK.
Некоторые сочетания поставщика и версии могут не иметь архива для Windows.

По умолчанию выбраны Oracle и Java 25. Размер архива зависит от выбранной
сборки. Для варианта по умолчанию это около 200 МБ. Во время скачивания
интерфейс показывает объём и проценты, затем отдельно отображает распаковку. JDK
устанавливается только в `launcher\java`. Лаунчер не меняет `PATH`, не пишет
настройки Java в реестр и не создаёт системную установку.

Если foojay публикует SHA-256 для выбранной сборки, лаунчер сверяет с ним
скачанный архив. При ошибке скачивания или несовпадении суммы частичный файл
удаляется. Распаковка идёт во временный каталог, поэтому неудачное обновление
не повреждает уже рабочий JDK.

## Совместимость с игрой

Таблица адресов собрана для `pureHD.exe` версии `2.0.2.118`, community-обёртки
HD. Если в папке находится другая версия или исполняемый файл без сведений о
версии, лаунчер показывает предупреждение с найденной и ожидаемой сборкой и
кнопкой Fix?. Та же кнопка Play сначала открывает диалог с тремя вариантами:
Cancel, Download pureHD и Run anyway. Run anyway запускает игру как есть, но
моды могут работать неправильно, поскольку адреса хуков относятся к другой
версии.

Download pureHD скачивает `sacred.purehd.zip` с ancaria.dev, сверяет SHA-256,
зашитый в лаунчер, и кладёт `pureHD.exe` и `pHD.dll` рядом с игрой. Исходный
исполняемый файл игры не трогается, а более старые копии этих двух файлов
сначала переносятся в `launcher\purehd-backup`. Закрытие диалога загрузку не
останавливает, для этого есть кнопка Abort. После установки предупреждение
пропадает, а Play запускает `pureHD.exe`.

Оригинальные файлы Sacred не патчатся, не переименовываются и не заменяются.
Изменения применяются в памяти запущенного процесса и исчезают после его
завершения. Лаунчер записывает только свои файлы в `launcher` и управляемые
пользователем jar-файлы в `mods`, а по запросу ещё `pureHD.exe` и `pHD.dll`
рядом с игрой.

Если Sacred Gold установлена в `Program Files`, запускайте лаунчер от имени
администратора. Без повышения прав Windows может запретить запись в папку игры.
Администраторские права также нужны, если сама игра запущена с повышением,
иначе хост Frida не сможет к ней подключиться.

## Дополнительные параметры и диагностика

Поле Extra flags for Sacred разбивает введённую строку по пробельным символам и
передаёт полученные аргументы исполняемому файлу игры. Флажок Show the console
while playing открывает консоль с выводом хоста после нажатия Play. Запуск
`Sacred Mod Loader.exe --debug` открывает консоль сразу и отмечает этот флажок
для текущего сеанса.

Свёрнутый блок Hooks перечисляет точки подключения, о которых сообщил хост.
Отключённая точка не устанавливается при следующем запуске. Щелчок по имени
модуля включает или выключает всю его группу. Этот блок нужен для поиска
проблемного хука без ручного редактирования JavaScript.

## Сборка

Для сборки отдельного checkout достаточно Go 1.26. Скрипт скачает
`protocol.exe`, `api.jar` и `zygote.jar` из публичных релизов, закреплённых в
`dependencies.json`. Сейчас там закреплены `protocol` версии `0.101.0` и
`coderpack` версии `0.102.0`. Агент отдельно не скачивается: его JavaScript
вместе с таблицей адресов минифицирован и встроен в `protocol.exe`.

Если рядом находятся checkout репозиториев `protocol` или `coderpack`, скрипт
собирает найденные компоненты из исходников, а недостающие скачивает. Порядок
теперь важен: сначала coderpack, чтобы появилась таблица адресов, затем хост,
которому через `PROTOCOL_AGENT` указывается, какого агента в него встроить.
В скачанном `protocol.exe` находится агент того релиза coderpack, который
закреплён в его собственной сборке; если рядом был checkout coderpack, скрипт
об этом предупреждает. Для полной сборки из исходников нужны JDK 21, Python 3.11
и Rust 1.98 с MSVC и LLVM. Пакет `frida-sys` запускает bindgen, которому
требуется libclang.

```powershell
pwsh tools/build.ps1         # собрать payload, затем сам исполняемый файл
pwsh tools/build.ps1 -Bump   # то же, но сначала поднять патч-версию в .version
pwsh tools/install.ps1       # собрать и скопировать результат в папку игры
```

Параметры `-Protocol`, `-Coderpack` и `-Mappings` задают другие пути к
checkout. Значение `none` для первых двух принудительно включает загрузку
соответствующих готовых релизов. При сборке `coderpack` скрипт передаёт
`mappings.json` из указанного checkout, если файл существует. Иначе
`coderpack/tools/addr.py` использует собственную цепочку поиска:

```powershell
pwsh tools/build.ps1 -Protocol none -Coderpack none
```

Именно этот путь использует CI.

Путь к игре `tools/install.ps1` берёт из `.local.settings`, который не
коммитится. Файл содержит одну строку:

```
sacred=D:\SteamLibrary\steamapps\common\Sacred Gold
```

Скрипт очищает и заново создаёт `install/payload`, затем помещает туда хост,
`api.jar`, `zygote.jar` и файл `VERSION`. Моды в payload не добавляются, а
скрипты агента больше не помещаются туда вовсе: вместо этого скрипт спрашивает
подготовленный хост о точках подключения командой `protocol.exe --hooks`, потому
что хост, не назвавший ни одной, собран без агента. После этого `go build`
встраивает подготовленные файлы и ресурсы Windows в
`dist/Sacred Mod Loader.exe`.

Текущая версия `0.103.1` хранится в `.version`. Её копия попадает в payload и
позволяет лаунчеру решить, нужна ли повторная распаковка. При запуске с `-Bump`
скрипт увеличивает последнюю часть версии до сборки.

CI работает для pull request, ручного запуска и каждого push в `master`. После
сборки он выполняет:

```powershell
go vet ./...
go test ./... -count=1
```

На ветке `master` CI публикует `dist/Sacred Mod Loader.exe` и создаёт тег
`v<version>`, только если такого тега ещё нет.

| Каталог | За что отвечает |
|---|---|
| `install` | Встроенный payload и его распаковка в папку игры |
| `mods` | Чтение `META-INF/declaration.toml` из jar и проверка совместимости |
| `registry` | Репозитории модов, установка, обновление, удаление и значки |
| `hooks` | Имена точек подключения, полученные от хоста в папке игры |
| `conf` | Настройки в `launcher\launcher.json` |
| `game` | Запуск хоста и игры, ожидание завершения |
| `java` | Поиск, загрузка и распаковка JDK |
| `ui` | Окно WebView2 со встроенной страницей |
